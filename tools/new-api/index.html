New API · 功能通俗指南

把一堆 AI 接口，理成一件顺手的事

New API 是一个大模型接口的聚合与分发平台。这份指南用大白话，讲清它最常用的四块：渠道、计费、令牌与高可用。

想象你开了一家 “AI 中间商”：上游从 OpenAI、Claude、Gemini 等多家进货，下游把一个统一接口交给你的应用或同事使用。New API 就是中间那张调度台——统一入口、统一计费、自动挑选最合适的上游。

三个角色，先认清

Channel

渠道

你的“进货渠道”。每个渠道对应一个上游账号——密钥、地址、以及它能跑哪些模型。

Token

令牌

你发出去的“门禁卡”，就是 sk- 开头的 API Key。谁想用你的服务，就拿一张令牌。

User / Group

用户 · 分组

谁在用、用哪一档价格。分组决定折扣倍率，以及能走哪些渠道。

一次请求，怎么走完

  1. 应用带着令牌请求——用 sk-xxx 调用某个模型，比如 gpt-4o。
  2. 校验令牌——额度够不够？这个模型允不允许？没过就直接拦下。
  3. 挑选渠道——按“模型 + 分组”筛出可用渠道，再按优先级和权重选一个。
  4. 转发上游——把请求发给选中的渠道，拿回结果（支持流式返回）。
  5. 扣费并记录——按倍率扣除额度，写一条明细日志，最后把结果返回应用。

记住这条链路：令牌管“谁能进、花多少”，渠道管“从哪家上游出去”，倍率管“这一趟扣多少额度”。后面几个标签页就是把这三件事分别讲透。

渠道是 New API 的核心。同一个模型可以配多个渠道，系统帮你自动挑、自动切。而“怎么挑”，全靠两个常被搞混的设置：优先级和权重。

优先级 vs 权重

Priority · 决定“先用谁”

优先级

数值越高越优先。系统总是先用最高优先级那一档；只有当它们全挂了，才降级到下一档。

→ 这是“主备 / 梯队”关系。

Weight · 决定“同档怎么分”

权重

同一优先级的多个渠道之间做加权随机。被选中的概率 = 它的权重 ÷ 同档所有权重之和。

→ 这是“负载均衡”关系。

一个例子就懂

三个渠道都能跑 gpt-4o：

渠道优先级权重实际分到的流量
A103约 75% 最高档，按 3∶1 分
B101约 25% 最高档，按 3∶1 分
C51000%（备用） 优先级低，轮不到它

正常情况下流量只在 A、B 之间分——C 的权重再高也没用，因为它优先级低。只有当 A 和 B 都不可用时，才会兜底切到 C。

一句话：优先级选梯队，权重在梯队内按比例分流量。权重是相对值——3∶1 和 30∶10 效果完全一样。

渠道还能做这些

模型映射 / 重定向把请求里的模型名改写成上游真实的模型名。比如对外统一叫 gpt-4，实际指向某个具体部署。
渠道分组给渠道打上分组标签，配合用户分组做“贵渠道只给高级组”的隔离。
自动禁用与恢复渠道连续报错会被自动拉黑，避免继续把请求送进坏渠道；稍后自动重试、恢复后自动启用。
一键测试测渠道通不通、测响应速度，方便上线前体检和日常排查。

New API 用 “额度（quota）” 作为内部通用货币。各家模型的真实价格，通过一套“倍率”折算成额度来记账。搞懂倍率，就看懂了每一笔扣费。

额度是什么

额度是平台内部的记账单位。默认 500,000 额度 = 1 美元（可在后台设置里改）。用户充值得到额度，每次请求按倍率从额度里扣。

三种倍率

Model ratio

模型倍率

这个模型每 token 有多贵。越强的模型倍率越高——它是价格的基准。

Completion ratio

补全倍率

输出通常比输入贵，用它给输出 token 加价。比如 3 = 输出单价是输入的 3 倍。

Group ratio

分组倍率

给不同用户组打折或加价。VIP 组 0.8（打八折），普通组 1.0。

计费公式

# 每次请求消耗的额度 消耗额度 = 模型倍率 × 分组倍率 × ( 输入tokens + 输出tokens × 补全倍率 ) # 换算成钱（默认） 实际花费($) = 消耗额度 ÷ 500,000

小例子

模型倍率 1、分组倍率 1、补全倍率 3；本次输入 1000 token、输出 500 token：

额度 = 1 × 1 × ( 1000 + 500 × 3 ) = 2500 花费 = 2500 ÷ 500,000 ≈ $0.005

还有缓存倍率等更细的项——命中提示词缓存的那部分 token 会更便宜。具体默认值随版本与配置不同，以你后台的实际设置为准。

令牌（Token）是你发给使用方的钥匙。每张令牌都能单独设规则，互不影响——这让你可以精细地控制“谁、能用什么、能花多少”。

一张令牌能设什么

额度上限这张卡最多能花多少额度，也可以设为“无限”。花完即停。
有效期设置过期时间，到点自动失效——发临时钥匙时很好用。
模型限制只允许调用指定的几个模型，防止有人拿你的卡去跑贵模型。
分组这张卡走哪一档价格与哪些渠道，由它绑定的分组决定。
IP 白名单只允许指定 IP 使用，钥匙泄露了也没法在别处调用。

用户与分组

用户归属到某个分组，分组决定它的倍率与可用渠道。这让你能轻松区分不同待遇——比如“内部同事 / 付费客户 / 免费试用”各走一档，同一套后台管到底。

充值与兑换码

支持用兑换码（redemption code）充值额度，也可对接在线支付。适合批量发放试用额度、或做分销：生成一批码，发出去，用户自己兑换。

配好之后，剩下的就交给系统。New API 的一系列高可用与运维能力，让多渠道自动分流、坏了自动切、用量看得见。

稳定性

负载均衡

多渠道 + 优先级 + 权重，让流量自动分摊，并优先走高优先级的渠道。

自动重试 · 故障转移

某渠道请求失败时，自动换下一个可用渠道重试，使用方基本无感。

健康检查

定时或手动测试渠道可用性与速度；异常自动禁用，恢复后自动启用。

日志与统计看板

每次请求都有明细（模型、token、消耗、耗时、渠道）；看板汇总用量与花费，方便对账排查。

兼容性

一个入口，接住多种协议

对外可用 OpenAI 兼容格式统一调用，你的现有代码几乎不用改；对内可对接 OpenAI、Claude、Gemini 等多家上游。

同时支持流式输出、函数调用（function calling）、向量（embedding）、重排（rerank）、绘图等常见能力——把杂七杂八的接口收拢成一套。
